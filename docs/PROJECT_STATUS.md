# 项目现状与阶段总结

更新日期：2026-11-11。当前阶段：pipeline 整理与端到端验收已完成，可接入数据集和评价模块。

## 项目做什么

这个项目研究如何把参考照片里的材质迁移到另一张照片的物体上。例如输入一张南瓜照片和一张陶瓷杯照片，生成外形仍像南瓜、表面具有陶瓷外观的图像。项目采用 ZeST 的基本路线，并研究两个额外组件：用 CLIPSeg 从参考图里找到文字指定的材质区域，以及用跨注意力调整材质特征。

目前的交付物是可运行、可记录配置和中间结果的实验 pipeline；还没有正式的效果比较结论。

## 已完成的能力

- `material_transfer/` 提供统一 Python API，包含配置、图像准备、参考分割、特征融合、生成、清单读取和结果保存。
- A/B/C/D 四组独立配置：A 基线；B 仅参考分割；C 仅特征融合；D 两者同时开启。
- 单例命令、CSV 批量运行和 Gradio 界面使用同一套生成代码。目标 mask 和深度图可外部提供，也可自动生成。
- 每次运行保存输入、中间图、结果和 `run.json`，记录配置、依赖版本、实际组件开关、随机种子、代码指纹和耗时。
- 已修复目标 mask 提取、CLIPSeg 接入与位置编码兼容、多头 attention 处理、短语子词选择、重复加载 UNet 和未知参数漏传等问题。
- 安装要求在 `pyproject.toml` 中定义，已验证环境的解析版本保存在 `requirements-lock.txt`。原型代码保存在 `experiments/legacy/`。

## 验证范围

已在 NVIDIA A40、Python 3.10、PyTorch 2.5.1 / CUDA 12.4、Diffusers 0.32.2 环境验证：

| 验收项 | 结果 |
|---|---|
| 依赖完整性 | `pip check` 通过 |
| 回归测试 | 9 项通过，不下载模型权重 |
| Gradio 服务 | HTTP `/config` 和 `/gradio_api/info` 检查通过 |
| A/B/C/D 真实生成 | 同一官方示例四组均生成 1024×1024 图像 |
| 中间结果 | B/D 保存 reference_mask；C/D 保存 attention_mask |
| 公平输入检查 | 四组 target/exemplar/target_mask/depth/init 文件哈希与包代码指纹一致，四张输出互不相同 |
| 自动输入准备 | 未提供 mask/depth 时，完成 rembg + DPT + A 组生成 |

示例来自 ZeST 的南瓜目标图与陶瓷杯参考图，seed=42、配置 steps=30。strength=0.9999 时实际执行 29 个去噪时间步。单次生成阶段约 9.7–10.2 秒、CUDA 峰值分配约 15.1–15.7 GiB，排除主干加载。这些是单例功能检查记录，不是经过重复计时的性能评测，也不构成其他硬件的最低显存要求。

模型权重、输入数据、生成结果和本地日志不纳入源码仓库。协作者可按 [README 的复核示例](../README.md#复核示例) 自行生成四组对比图。

## 协作接口

安装、模型配置、单例运行、批量运行和 UI 使用方法见 [README](../README.md)。

CSV 清单指定每对目标图、参考图、目标 mask、深度图、材质描述和 seed。批量入口每个进程只加载一次模型。评价代码通过 `run.json` 的 `artifacts` 字段获取文件，通过 `config` 获取配置；无需依赖界面或复制生成逻辑。

后续可以分别推进方法复核、数据与指标、实验与图表。共同使用固定清单和结果协议，保持方法间输入与参数可比较。

## 当前限制与下一步

1. 正式评测集、人工标注、评价指标和参数扫描尚未实施。单例跑通不能回答哪个方法更好。
2. 示例目标 mask 是近似手工多边形，只用于流程检查；正式实验需要确认过的目标 mask 和参考图标注。
3. A 组使用 Diffusers 原生 IP-Adapter 并修正目标 mask，称为 ZeST-style 基线；尚未与官方实现做逐像素等价验证。自动 DPT 预处理也可能与原 DPT 脚本不同。
4. 自定义 attention 是未经训练对齐的研究分支。已观察到的注意力图对比度较低，图像变化本身不能证明准确定位了材质。
5. 四组正式比较应共享预计算 mask/depth、种子和主干参数，并区分纯材质参考与杂乱参考，保留成功和失败案例。

下一阶段先固定少量真实样本和清单，接入参考 mask IoU、背景保留等指标，再扩大四组实验。后续阶段继续记录交付、验证、限制和下一步，便于协作者接手。
